# Матклуб — by ddima_dev

## Олимпиадный уровень

Четвёртый уровень сложности — «Олимпиадный». Стартовая подборка: две задачи по математике (прыжок Виета и геометрический минимум на вписанной окружности) и две по физике (подвижный клин и электромеханическая цепь с конденсатором). Файл `dist/olympiad.js` подключён после интенсива. У всех задач постоянные ID, две подсказки, полный разбор с доказательством/обоснованием модели, проверка и типичная ошибка. Автоматически оценивается только числовой ответ, а не доказательство.

Олимпиадный фильтр показывает обе задачи выбранного предмета сразу, без ограничения текущим классом или алгеброй/геометрией; класс задачи указан на карточке. При возврате к обычному уровню стандартные фильтры возвращаются. Задачи входят в избранное, мастерскую, прогресс и облачную синхронизацию.

Проверки: `node scripts/check-olympiad.cjs` (независимый целочисленный перебор, оптимизация на окружности, динамика клина и RK4 цепи), `node scripts/check-olympiad-ui.cjs` (нужен jsdom). После изменения материалов запускай `node scripts/build-search.cjs`.


## Личный кабинет и облачный прогресс

Сайт обслуживает Cloudflare Worker `server/worker.mjs`: статика остаётся в `dist/`, API находится в `/api/`. Конфигурация `wrangler.jsonc` сохраняет имя `matclub1`, подключает `ASSETS` и D1 `DB` (`matclub-users`). Таблицы создаются идемпотентно при первом обращении; ручной SQL-запуск не нужен. Для публикации используется существующая интеграция GitHub → Cloudflare Workers (`npx wrangler deploy`). Отключать `run_worker_first` нельзя: главная страница получает состояние ученика до запуска учебных скриптов. Если база недоступна, учиться можно как гостю.

Регистрация: уникальный логин из 3–24 латинских букв/цифр/подчёркиваний без учёта регистра; пароль 10–128 символов; необязательный псевдоним и класс. Почта и телефон не запрашиваются. Пароли хранятся как PBKDF2-SHA256 с индивидуальной 128-битной солью и 100000 итераций (лимит Web Crypto Workers); открытые пароли не сохраняются. Сессия — случайный 256-битный токен в `__Host-` cookie с Secure/HttpOnly/SameSite=Lax на 30 дней; в D1 хранится только SHA256 токена. Смена пароля отзывает все прежние сессии. Восстановления забытого пароля без почты в этой версии нет.

API: `GET /api/me`, `POST /api/register`, `/api/login`, `/api/logout`, `/api/password`, `PUT /api/profile`, `GET/PUT /api/progress`, `DELETE /api/account` (с подтверждением текущего пароля; удаляет аккаунт, прогресс и сессии). Изменяющие запросы проверяют точный Origin. Вход, регистрация, смена пароля и синхронизация ограничены по частоте в D1. Истёкшие сессии и счётчики очищаются. Ответы API и персонализированная главная имеют `Cache-Control: no-store`; пользовательские данные безопасно экранируются при внедрении в HTML.

Синхронизируются решённые/избранные школьные задачи, мастерская с черновиками и рисунками, Python, C++, лабораторные журналы, настройки и графики. Размер облачного документа ограничен 1 МиБ; при превышении локальные данные сохраняются, интерфейс предлагает сократить большие черновики. Достижения вычисляются по сохранённому прогрессу; C++ использует самостоятельные отметки. Это учебная статистика, а не подтверждённые экзаменационные результаты.

`dist/account-bootstrap.js` применяет состояние до чтения localStorage учебными разделами. Гостевой прогресс можно перенести при регистрации. При входе в существующий аккаунт загружаются его облачные данные. Изменения отправляются с задержкой; недоставленные данные отмечаются в локальном кеше и переживают перезагрузку, обрыв сети и повторный вход. Оптимистичная блокировка по revision возвращает 409 при изменениях с другого устройства: пользователь выбирает версию, а скачиваемая резервная копия содержит обе. Изменение аккаунта в другой вкладке приостанавливает отправку до перезагрузки. При выходе/истечении сессии основные учебные ключи очищаются, поэтому данные предыдущего ученика не показываются как гостевые. Локальные резервные копии остаются в профиле браузера; они не зашифрованы. Для общего компьютера завершайте сеанс браузера.

Проверки: `node scripts/check-account.mjs` — реальные SQLite-транзакции через адаптер D1, регистрация, хеширование, сессии, CSRF, ограничения, изоляция учеников, версии, смена пароля и SSR; `node scripts/check-account-ui.cjs` (нужен jsdom) — кабинет, достижения, синхронизация, офлайн, конфликты, разделение аккаунтов и экранирование. Визуальный браузерный прогон в текущей среде недоступен.

Темы: типы, ввод, ветвления, циклы, строки, vector, функции, ссылки/const, структуры, классы, map, STL, бинарный поиск, рекурсия, исключения, потоки, RAII/unique_ptr, шаблоны и тестирование.

Редактор сохраняет черновики и самостоятельные отметки прохождения в `matclub-cpp-v1`. Можно скачать `main.cpp`; компиляция пользовательского кода в браузере не выполняется. Примеры и эталонные решения проверяются локальным компилятором C++17, а вопросы на понимание проверяются прямо на сайте. Отметка прохождения не означает автоматическую проверку программы.

Проверки: `python3 scripts/check-cpp.py` (требуется g++, 77 запусков примеров и решений с `-Wall -Wextra -Wpedantic -Werror`) и `node scripts/check-cpp-ui.cjs` (требуется jsdom). ## Физическая лаборатория

Отдельный раздел навигации «Лаборатория» (на телефонах — «Опыты»), без пометки альфа/бета. 20 готовых опытов: бросок под углом, наклонная плоскость, столкновение тел, маятник, пружина, Архимедова сила, гидростатика, идеальный газ, нагрев, смешивание, закон Ома, соединения резисторов, RC-цепь, индукция, бегущая и стоячая волны, преломление, линза, фотоэффект и распад.

Каждый опыт содержит управляемую SVG-установку, показания, график с закреплением предыдущих условий, формулы, границы применимости, план исследования и расчётную задачу с проверкой ответа. Динамические опыты запускаются только по команде пользователя; доступны пауза, шаг, шкала времени и скорость. Один проход шкалы занимает около 12 секунд при 1× независимо от физической длительности, которая всегда указана отдельно. При уходе из раздела или скрытии вкладки воспроизведение останавливается.

Параметры, гипотеза, вывод и до 120 измерений на каждый опыт сохраняются в localStorage (`matclub-laboratory-v1`). CSV содержит параметры, показания и заметки; график экспортируется в SVG. Запуск моделей не требует внешнего API, интерпретатора или библиотеки графиков. Все вычисления детерминированы; распад показывает математическое ожидание, а не случайные события.

Исходники: `dist/lab-models.js` (чистые расчёты и материалы), `lab-scenes.js` (установки), `lab.js` (интерфейс и журнал), `lab.css`. Ссылки `/?lab=projectile` и `/?lab=lens` открывают соответствующий опыт. Генератор `node scripts/build-search.cjs` создаёт также каталог `/laboratory/` и 20 справочных страниц; карта сайта теперь содержит 149 URL.

Проверки: `node scripts/check-laboratory.cjs` — физические инварианты, размерности, границы, производные и диапазоны параметров. `node scripts/check-laboratory-ui.cjs` — интеграционные проверки в JSDOM (нужен пакет `jsdom`, можно использовать `NODE_PATH` существующей QA-установки). Проверены все 20 интерфейсов, пресеты, измерения, фильтры, сохранение, экспорты и глубокие ссылки. Визуальный браузерный прогон в среде разработки недоступен; JSDOM не проверяет фактическую раскладку и отрисовку.

Независимый статический сайт: математика 6–11 классов и физика 7–11 классов.
Содержимое `dist/` работает без ChatGPT, серверного приложения и внешних API.

## Бесплатная публикация на GitHub Pages

1. Создай публичный репозиторий `matclub` в своём аккаунте GitHub.
2. Загрузи содержимое этой папки в ветку `main`, сохраняя структуру каталогов.
   Не забудь скрытую папку `.github` с файлом `workflows/pages.yml`.
3. В репозитории открой Settings → Pages → Source → GitHub Actions.
4. Открой Actions → Publish Matclub → Run workflow (или сделай новый коммит).
5. После успешного выполнения ссылка появится в Settings → Pages.
   Обычно это https://ИМЯ-АККАУНТА.github.io/matclub/ .

Для загрузки через Git:

```sh
git init -b main
git add .
git commit -m "Publish Matclub"
git remote add origin https://github.com/ИМЯ-АККАУНТА/matclub.git
git push -u origin main
```

## ИИ-помощник

Плавающая кнопка открывает чат, включая мастерскую задач. На телефоне используется полноэкранное окно. `/api/assistant` обращается к Cloudflare Workers AI через привязку AI, основная модель `@cf/google/gemma-4-26b-a4b-it`, резервная `@cf/meta/llama-3.1-8b-instruct-fast` при недоступности модели или отсутствии её активации; клиент не получает ключей. ## Устойчивость API (2026-11-08)

Регистрация создаёт пользователя, прогресс и первую сессию одной транзакцией. Смена пароля одновременно обновляет хеш, отзывает старые сессии и создаёт новую; условие по предыдущему хешу отклоняет устаревший запрос. Вход и удаление аккаунта также проверяют актуальность пароля при записи. Синхронизация прогресса сохраняет проверку ревизии: параллельная запись не затирает свежие данные.

Чтение JSON ограничено размером в байтах и общим ожиданием 10 секунд, отменённые и оборванные потоки обрабатываются отдельно. Неудачная очистка просроченных записей не ломает основной ответ. Гостевая главная страница и HEAD не обращаются к базе для загрузки профиля. Личные страницы по-прежнему имеют `private, no-store` и `Vary: Cookie`.

`GET /api/health` — лёгкая проверка доступности Worker, содержит `scope: worker` и версию сервера. Она не проверяет состояние D1 или провайдера ИИ. Каждый ответ содержит `X-Request-ID`, `X-Content-Type-Options` и `Referrer-Policy`. Неожиданные ошибки логируются с номером запроса и типом ошибки, без паролей, токенов, тела запроса и содержимого прогресса.

## Серверная надёжность, версия backend-2026-11-08.2

`server/database.mjs` отвечает за запуск D1, проверку готовности и очистку. Параллельные запросы разделяют одну инициализацию; после ошибки повтор откладывается на 15 секунд в пределах экземпляра Worker. Очистка запускается только после успешной инициализации, удаляет до 200 записей каждого вида и не влияет на основной ответ. Схема D1 и существующие данные совместимы; миграция не требуется.

Запись профиля/прогресса, смена пароля и удаление аккаунта проверяют действующую сессию непосредственно в SQL записи. Запрос, начатый до отзыва или истечения сессии, не может записать данные после этого. Удаление пользователя атомарно удаляет сессии и прогресс через существующие внешние ключи D1 с `ON DELETE CASCADE`.

Если ответ успешного сохранения потерялся в сети, точный повтор документа с предыдущей ревизией возвращает уже сохранённый результат. Отличающиеся данные по-прежнему вызывают конфликт 409; автоматического слияния или перезаписи нет. Это не меняет формат клиентского протокола. Главная страница и HEAD используют одинаковые private/no-store и Vary: Cookie; статические валидаторы не применяются к персонализированному HTML.

`GET/HEAD /api/health` проверяет только Worker. `GET/HEAD /api/ready` отдельно проверяет доступность четырёх основных таблиц D1 без чтения ученических данных и без изменений базы. Проба ждёт до двух секунд, результат и параллельные вызовы объединяются на пять секунд в пределах экземпляра Worker. Ответ 503 содержит Retry-After; доступность AI эта проба не проверяет. Таймаут ожидания не отменяет уже отправленный запрос D1. При поздней ошибке основной AI-модели после таймаута резервная модель не запускается; уже выполняющийся запрос провайдера может завершиться позже.

Полный серверный прогон: `node scripts/check-backend.mjs` (Node 24, без npm-зависимостей). Проверяются транзакции, реальный SQLite и PBKDF2, чужие аккаунты, конфликтующие и повторные записи, отзыв/истечение сессии между чтением и записью, отказ/восстановление базы, таймауты, очистка и квоты AI. GitHub Actions запускает этот прогон при изменениях сервера. Существующая автоматическая публикация Cloudflare независима от Actions; workflow сам по себе не блокирует деплой. Это проверки корректности и имитация отказов, а не измерение предельной нагрузки.
